## 状态与流程检查

逐页记录适用的入口、列表、详情、选择、确认、结果和返回；再判断空态、搜索无结果、未解锁、条件不足、进行中、已完成、失败与异常是否适用。领取奖励等只用于已核实存在相应业务的页面。不适用需注明原因，不要求每屏机械复制全部状态。

经营核心流程至少明确以下关系，使用图和状态预览表达；本阶段图中点击不会执行真实游戏操作：

1. 选择场景 → 查看目标 → 载入园区 → HUD/暂停/保存/返回。
2. 选择设施 → 类型/设计/研究条件 → 放置与费用 → 轨道/出入口/队列 → 测试 → 测试结果 → 开放或修正。
3. 设施列表 → 设施详情各适用子页 → 运营、定价、维护/故障、收入与统计 → 关闭/拆除确认。
4. 地形/水体/道路/景观工具 → 尺寸/高度/材质/方向 → 预览、无效放置与资金不足 → 确认/取消。
5. 游客或员工列表 → 个体信息/需求/工作区/状态 → 追踪/拾取/管理 → 返回列表。
6. 财务/研究/营销/目标 → 条件、投入、进度与结果；结果不能冒充实际模拟回执。
7. 多人服务器列表 → 连接/密码/同步/失败 → 玩家与权限/聊天 → 断线/返回；没有与账号登录/角色创建混为一体。
8. 场景/轨道编辑相关步骤 → 校验 → 保存/导出或错误修正；高级工具按源码现有功能范围记录。

## 批次和最终验收

每批检查对应新增图片与清单，不用旧项目或未变历史报告替代本次像素检查。建议通用控件 → 园区HUD/启动 → 建造与设施 → 经营统计 → 游客员工/多人 → 编辑器与辅助的顺序推进。所需母板、图标数量等是制作计划；只有manifest和实际像素核实后才计入完成数量。

最终结果需分别报告：

- 覆盖统计：总清单应交项/已有文件/视觉通过/待修/缺失，按系统与页面状态拆分。
- 文件检查：真实尺寸、格式、哈希、Alpha、状态尺寸和Border合法性；清楚区分机器检查与人工视觉检查。
- 视觉检查：实际查看的整屏/拼图/原尺寸资源与九宫格预览路径，具体问题和处理结果。未逐屏实看时明确剩余范围。
- 来源检查：模型生成图、AI编辑图、直接复用图和机械派生图分别统计，未知实际模型/质量不因交付而改成已确认。
- 交付入口：整套预览、正式资源目录、功能覆盖清单、Unity建议、来源与关联记录、接入待办。参考仓库本身不混入后续成果包。

状态名称建议为“待制作”“制作中”“待视觉验收”“待修”“视觉通过”“不适用”。总体仅在所有适用应交项真实完成、检查通过且缺失为零后标为“整套美术验收完成”；仍有缺失时准确写出具体缺口及已交付范围。
