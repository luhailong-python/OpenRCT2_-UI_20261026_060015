# 下一阶段 Unity 接入事项

当前包交付静态整屏、控件/图标/卡面、状态与流程图、文字布局、源码功能映射及导入建议。本阶段没有创建Unity工程、Prefab、场景或C#代码，也没有把图片预览当作运行证明。

1. 确认正式游戏名、目标平台和Unity版本；当前“云游仙苑（暂名）”及1920×1080桌面横屏是美术排版约定。
2. 按`assets/manifest.json`导入单件PNG，实测Alpha、MaxSize、Pivot、Sliced Border L/B/R/T；保持各按钮状态画布一致，禁止把整屏PNG直接当作可交互窗口。
3. 导入随包OFL字体并建立TMP字体/字形回退；测试中文长名称、金额、缩放比例和列表滚动，不把设计示例值硬编码成游戏真值。
4. 建立HUD、窗口、弹窗、提示与选择工具的层级和遮挡；按逐屏`.layout.json`重建动态文字、控件区域与交互。源码控件样式核对板的坐标仅用于美术合同展示，不能直接当作产品窗口的完整布局坐标。
5. 依据功能总清单和`control-resource-mapping.json`逐项绑定窗口、页签、即时设置、下拉、数字输入、列表、图表和视口。每条控件的最终产品位置及事件绑定需在引擎中逐项回写验证。
6. 接入真实园区渲染与建设选择预览；本包的园区背景和设施卡面是UI展示图，不是轨道分段、碰撞、可行走地图、全部设施世界精灵或可操作模拟场景。若后续需要重制世界渲染资源，按独立世界美术生产合同制作。
7. 核实设施类型能力：关闭/测试/模拟/开放、车站与入口出口、步道连通、故障/事故、维修和价格；商店不套用所有过山车检查。
8. 实现游客需求与消费、员工岗位/巡逻、研究自动解锁、财务/贷款/营销、场景目标与结果，并按状态合同显示具体失败原因。
9. 实现场景编辑七步前置校验、对象依赖、保存/覆盖和缺失对象处理；多人联机单独验证版本/密码/下载同步、权限和失同步反馈。
10. 在目标分辨率做实际引擎截图、输入焦点/模态阻挡、按钮状态和滚动检查，再做真实存档、经营及网络运行测试。美术静态验收结果不能替代这些结果。

任意第三方插件的业务内容未由参考主仓限定，当前提供原生插件控件的统一皮肤与排版合同；实际插件应逐个补充内容与运行验收。OpenRCT2商业原作数据没有随源码仓库取得，本包不包含其商业精灵、商用场景或音频。
