# Image 项目长期指令

本文件适用于本仓库全部目录、制作窗口、子任务及换电脑后的接续。开始工作和每次新的生图／AI 修图前读取本文件。用户当前明确指令优先；模型与逐图记录、素材保留、风格及专项交付合同按下文执行。

## 图像设置、生成入口与逐图记录

- 生图或编辑前读取 [统一图像设置](config/image-generation.json)和[执行策略](docs/IMAGE_MODEL_POLICY.md)。默认型号与质量只在该 JSON 维护；每个新任务核对官方最新正式版本与最高质量，出现更新型号或更高质量档位且入口支持时，直接更新配置用于新图，不固定在旧版本或旧最高档。同一批次保持一致，用户本次显式选择优先。
- **逐图记录版本：** 每张新生成或 AI 编辑的图都按[逐图生成记录](docs/IMAGE_MODEL_POLICY.md#逐图生成记录)保存模型版本、质量、时间和来源证据，区分配置目标、实际提交参数与实际返回值。工具未披露的版本／质量标记为未确认；配置升级不改写旧图记录，裁切／缩放图关联原图来源。
- 优先使用宿主内置 `image_gen`。官方已宣布新版面向 ChatGPT、ChatGPT Work 和 Codex 开放；按配置中的产品与最高画质目标执行。有型号／质量参数时显式传入配置值；无参数时使用宿主管理的内置路径，记录实际可得证据，不把提示词或公告当作已显式锁定 API 分支和质量。具体官方证据见执行策略。缺少型号选择器或返回元数据时，继续使用现有内置入口并如实记录证据。
- API/CLI 是用户明确选择的备用路径，默认从同一 JSON 读取模型与质量。单独计费授权和凭证要求保持不变；参考图读取故障优先排查输入通道，不等同于必须配置 API 密钥。新增付费路线、订阅、预算或凭据变更仍需用户明确授权。

## UI 风格：以用户指定的 designs 成图为首要依据

所有 UI、窗口、面板、按钮、页签、边框、图标及切片，统一沿用本仓库 `designs` 已确认的**道家 Q 版高清手绘风格**。用户特别指定以下两张图片，优先于旧文字概括和其他游戏截图：

1. **邮件界面主参考：** [designs/mail-ui-v1/01-mail-event.png](designs/mail-ui-v1/01-mail-event.png)。
2. **组队界面主参考：** [designs/team-ui-v2/team-ui-v2.png](designs/team-ui-v2/team-ui-v2.png)。

制作 UI 前实际查看这两张现存原图，并按任务需要在生成／编辑调用中实际附上参考图；不能只写文件名或用文字提示代替图片参考。再查看同功能的已确认 `designs` 成图，承接控件层级、尺寸、状态和既有设计。检查实际路径是否存在；旧文档曾写“邮件图缺失”不代表当前仍缺失。若新环境缺少指定图，报告缺失，不从已删除目录或旧 Git 自动补回，不擅自换风格。

必须保持的视觉特征：

- **配色与材质：** 玉绿、青绿为主色；象牙米白、暖米色纸绢质感为大面积面板；暖金细边与柔和雕饰协调。红穗、朱砂、桃花粉、灯笼暖光适量点缀，保持文字区清楚。
- **形状与画法：** 圆润饱满的框板和按钮、柔和云纹与如意卷边、细腻手绘明暗和适度金玉质感。延续两张主参考的精细完成度，避免写实人物、塑料玩具高光、粗糙拼贴、模糊拉伸或密集噪点。
- **道家元素：** 太极、葫芦、玉珠、流苏、云气、仙山亭阁与节庆装饰，依界面用途适量使用。春节、元宵、中秋氛围自然融入，不遮挡信息与操作。
- **控件层级：** 玉绿金边的标题牌、主要操作按钮与选中状态；米白底的正文、列表、次要按钮和卡片。金色细分隔、清楚的留白、对齐与可读中文，延续邮件图及组队图的层级；不照搬示例中的测试数据。
- **人物与小物：** 道家 Q 版的大头短身、圆润表情，保留现有角色的身份、服装、法器与宠物特征，不把不同人物套成同一张脸。
- **功能与风格分开：** 其他游戏截图默认仅参考功能、内容与布局；不得用其画法、皮肤或角色替换上述用户指定风格。正式游戏名、文案与状态按当前任务要求，不擅自照抄其他游戏名称。

切片沿用对应已确认整屏／原画的边框、颜色、材质和比例。依实际合同处理透明通道、九宫格和尺寸；不得把裁切、放大或拼接声称为新模型生成或原生高清细节。

制作、修改、实现 UI 或重新切图，以及收到其他游戏截图时，先读 [UI 制作规范第 2 节](qdao_ui_redesign_v5/UI_SPEC.md#2-统一视觉与控件层级)，再按上述指定成图和任务功能执行。模型升级只提高生成能力，风格保持不变；用户后续明确改风格时再调整。

## 地图和其他素材保持同一美术方向

人物、怪物、NPC、宠物与场景承接同一套道家 Q 版画法、配色和材质，具体身份与布局以各自已确认图为准。

主城地图高清分块、拼接与切图前，先读 [主城地图切图规范](主城地图切图规范.md)：主城整图65536×65536，每个正式图块4096×4096，16×16共256块，采用圆润饱满、明亮干净的Q版美术。该规范只管主城切图；客户端加载与接入见 [客户端说明](../mmorpg-client/Docs/CityTiles4K.md)，其他地图按各自生产合同执行。

主城、渔村、八仙岛的当前地图继续按已确认布局与各区生产合同制作：日景、自然浅灰／青灰石地，春节细节在建筑、门窗、灯笼中体现，元宵与中秋适量点缀；道路连通，树靠建筑或院墙。UI 邮件图中的夜景、人物、文字和界面框不画入纯地图。完整图、原生切片、内部检查和全图验收分别记录，不把放大概览当作已完成的原生 4K 图块。

## 现存图片与当前制作流程

- **制作提速（2026-10-13）：** 保持当前图像质量、布局及尺寸合同。优先补齐本区已达 12—15/16 核心的图块，再沿已稳定边缘连续推进；若该片会传播几何或布局错误先修正。每张新片先快速核对布局及相邻边，凑齐一块后集中检查内部接缝；已通过且输入哈希未变的检查直接复用，不反复扫描历史版本、重建总览或整包。非阻塞的局部问题写入待修列表，保持未通过状态；同一点连续两次返修无改善则保留最佳已有版本和具体问题，先做本区其他独立缺片，后续集中解决。不得把暂缓返修当作通过，也不以放大、模糊或程序画图代替原生细节。协调者负责总统计，制作窗口只维护本批必要源图、坐标、版本和检查记录。

- **2026-10-13 并行坐标分工：** 新的地图生成前读取 `docs/MAP_PARALLEL_SPLIT_20261013.json`。其中状态为 `allocated_root_reserved` 的坐标由列出的 worker 独占生产；原 owner 及其内部子工排除这些坐标，保留其他在制块。新 worker 仅写 manifest 指定的新目录，原区记录只读。此分工由用户要求继续分配未完成图块后，协调者核对当前无目标原生片、无目标在制坐标而划定；不依赖旧的待回执状态。若发现真实在途或已选源冲突，保存证据并暂停该冲突坐标，继续同批其他无冲突坐标。不能把本条当作原 owner 已回执的证明。

- **素材保留（2026-09-23 用户确认）：** 只保留最终用于游戏的图片、配套设计与接入所需文件；确认成品已落盘且当前引用完整后，删除原图、回退版本、拒稿和加工中间图，无需另存图片备份。保留逐图模型／质量／来源文字记录；仍是当前设计、正式资源或尚未导出成品的唯一在制稿，按实际用途核实后处理。本条覆盖旧文档中保留原图和回退副本的要求。新作使用新版本路径，保留其他制作窗口的当前稿；用户明确授权的图片编辑按该任务范围执行。
- 用户手动删除的目录不从旧 Git、旧清单或快照补回；不为迁移或恢复旧配置重新引入它们。当前根 `AGENTS.md` 是用户此次明确要求新增的长期指令。
- 本文件不授权删除 `docs`。其中仍有制作恢复指令、源文件映射、迁移核验资料及图片；重复模型／风格说明可在依赖迁移并核实后精简，不能直接整目录删除。
- **Git 历史（2026-10-20 接续落实）：** 后续保存和发布只维护最新已核验状态；统一发布的美术仓库目标为一个无父提交，每小时私有保存只替换最新记录，不累积提交链或额外素材快照。必要来源文字记录保留。准备保存、提交、上传或清理 Git 时先读 [Git 最新状态保留规则](docs/GIT_LATEST_STATE_POLICY.md)，继续遵守唯一上传者和固定批次约束；现有旧仓及未完成迁移不因本条自动删除。
- 制作窗口不操作共享 Git 的 HEAD、index 或 refs。首批迁移和统一推送继续由用户指定的唯一上传者处理；本对话每小时本地增量沿已核实的新基线，用私有对象库和 index 保存，不自动接回推送职责。
- 不重建、打断或热换正在捕获／上传的固定批次。根指令新增若不在当前固定截止点内，纳入后续提交；不得宣称已提交或已 push。

## 换电脑、换路径和接续窗口

- 将本文件与上述两张 UI 主参考一起纳入项目交付和后续 Git 提交，换电脑 clone／pull 后核实三者实际存在，再开始新图。规则和图片路径均相对仓库根目录，不依赖 `D:` 或旧电脑的用户目录。
- 新窗口先读取本文件；已有窗口接到本次规则更新后，在下一次生成／AI 修图前主动重读，不能假定旧会话会自动热更新磁盘上的指令。
- 换机并不自动安装模型、继承凭据或证明配置中的型号实际可用。每个新环境重新核实生成入口，按统一图像设置执行，并如实记录宿主实际提供的型号证据。
- 当前制作断点与迁移是否完成按实际进度和成功回执判断，必要时读取对应 `docs` 交接；不把长期风格规则当作已经完成制作或上传的证明。
- 制作游戏素材前，阅读 [README 的接手说明](README.md#给接手的-codex) 指向的交接与美术定调文档；换电脑时按 [工具移机说明](docs/AI_DESIGN_TOOLS_SETUP.md)确认内置工具或用户选择的 CLI、账号权限可用。本文件不负责同步账号、凭证和用户目录工具。

## 工作区目录约定（2026-10-20 用户要求）

- `E:\work` 顶层只保留 `image`、`mmorpg-client`、`xuanming-server-mmo`、`proto2mysql` 四个项目目录。
- 导出、迁移克隆、日志、构建包和验证产物放在所属项目的忽略目录或系统临时目录，不在工作区顶层新增 `tmp`、`builds`、备份目录或独立工作树。额外 Git 工作树使用托管位置或工作区之外的位置。
- 临时工作树完成后先核实独有提交及未提交改动已整合、必要验证已通过，再移除工作树。清理时只解除目录链接本身，不递归进入链接指向的主项目。
- 本约定不改变固定批次上传与唯一上传者的分工；不要为了清理目录切换共享 Git 的 HEAD、index 或 refs。
